# Librarian isolated extractor

Build `deploy/extractor/Dockerfile`, review/scan its dependencies and record the immutable local image ID. Trusted host construction may supply `containerExtractor(imageId)` as `SandboxedExtractor`. Tags and automatic pulls are refused; there is no HTTP selector or unsandboxed fallback. The production feature remains OFF.

Each extraction launches a fresh UID 65534 container: no network, no host mounts, read-only root, all capabilities dropped, no-new-privileges, 256 MiB memory/swap, one CPU, ten seconds per-process CPU, fifteen seconds wall time, 16 PIDs, 64 descriptors, 1 MiB file/output ceiling and a 16 MiB noexec/nosuid/nodev temporary filesystem. Input is bounded stdin; output is strictly decoded UTF-8. Overflow/deadline force-remove the container and reap the client; cleanup commands have their own five-second bound. HTML never loads subresources. Poppler handles PDF with a 100-page ceiling and no OCR. Active/encrypted/attached/form PDF names (including hex escapes), parser warnings, empty text and trailing non-whitespace payloads fail closed. This deliberately rejects some valid PDFs.

## Deployment ceiling and operational gate

This adapter is deployable only when the trusted ingestion executor runs directly on a dedicated Linux sandbox host with a local container launcher and a preinstalled reviewed image. Keep that host single purpose, deny inbound public traffic, provision no provider credentials in extraction containers, configure host egress rules independently, and maintain kernel/runtime/Poppler updates. Trusted application construction must inject this adapter; image presence alone does not enable ingestion.

The current hosted/Railway app image has neither Docker nor an isolated launcher. **It cannot safely use this adapter as deployed. Do not mount a Docker daemon socket into the public server.** An opt-in [authenticated private executor](executor/README.md) now implements a constrained signed byte/job protocol and an explicitly injected `remoteExtractor` client. Only the dedicated host runs Docker. The hosted runtime must explicitly wire that client; no env/config is automatically discovered and no hosted enablement occurred. Local private fixtures exercise this boundary, but deployed-host acceptance, private routing/firewall, key provisioning and full security review remain open. Hosted ingestion stays unavailable/OFF absent this explicit integration and the operational gates. Do not substitute an in-process parser or generic shell/HTTP callback.

## Reproducible private qualification

Run `deploy/extractor/qualify.sh` from a Docker Desktop/Linux host with Bun and OpenSSL installed. It builds a unique image, prints the exact image ID, runs dedicated fixtures and removes its tag. No shared compose stack, provider call, hosted enablement or real source data is used. To test a prebuilt immutable local image directly, set `TEST_LIBRARIAN_EXTRACTOR_IMAGE` and run the three test files listed in the script. Without that variable the container cases explicitly skip and are not evidence.

Fixtures cover real text/Markdown/inert HTML/text-bearing PDF; 100 accepted versus 101 rejected pages; empty/image-only, malformed, active-name-escaped, encrypted-name, attached-name and trailing-payload PDFs; output/MIME/missing-image/absent-adapter refusal. A private derived probe image uses the identical production launcher to attempt outbound networking, root writes and absent host paths; verifies UID/CPU/descriptor limits; and exhausts memory, CPU, wall time and stdout. It verifies no probe containers remain afterward. The TLS fixture maps a validated synthetic public pin to a private loopback TLS server only inside its injected test dialer; real hostname verification stays enabled. It tests identity encoding, fixed headers, successful streaming, wrong-host TLS refusal before HTTP, redirects, compressed/unsupported bodies, streamed overflow, truncated response, deadline, changed DNS and mismatched address families.

Limits: this is controlled-fixture qualification on the local Docker engine, not a kernel escape proof, parser fuzz campaign, dependency vulnerability scan or deployed egress-firewall test. Rejecting active PDF names is conservative lexical defense plus Poppler validation, not a complete proof against all PDF polyglots/obfuscated actions. Production release still requires adversarial PDF corpus/fuzzing, parser supply-chain review, deployed network/launcher acceptance and failure/restart teardown testing. CPU rlimit is per process; the one-CPU cgroup and wall deadline bound the whole job. A launcher/daemon outage can prevent forced removal; operators must reconcile orphan jobs on the dedicated host before service recovery.
