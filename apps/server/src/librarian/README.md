# Librarian foundation integration

Production stays OFF. The default `librarian` job reaps expired leases, then invokes the guarded runtime only when the global flag and persisted configuration permit it. Config/key writes and ingestion route registration never dispatch. No real credential or provider request was used in foundation verification.

Import frozen services from `index.ts`; the complete contract and additive signatures are in `docs/implementation/15-librarian.md`.

- `claimRun` preserves its original input and adds optional `inboxId` and `daily`. Inbox claims accept queued/ready unbound items in the same org/wiki; daily claims deduplicate by wiki and UTC date. The full run cap is reserved atomically.
- `withToolReceipt(deps,fence,{toolKey,inputHash},mutate,authorize)` runs authorization on every invocation, including replay. Content locking, current can()/agentPolicy(), mutations, activity and receipt must all use its supplied transaction. No external I/O or independent transactions. The runner's own receipt helper has the same requirement and separately invokes authorizeTool.
- `storeProposal` stores bounded untrusted prose through a receipt. `reviewProposal` serializes human review and requires authorization and a page creator using the same transaction. These are trusted service seams, not HTTP review endpoints.
- `subscribeRunCancellation` supplies `{signal,close}` using durable fence polling. `withRunSignal` closes automatically. Signals are advisory; every mutation still checks the transaction fence.
- `createLibrarianJob(deps,{provider,authorizeTool,tool},owner?)` composes the runner with ready-inbox/daily scheduling, cancellation, 401 disable and terminal accounting. All three adapters are required. No production instance is constructed. `finalizeExecution` can finalize accounting after lease expiry without authorizing content writes.
- `rotateAllProviderEnvelopes` rotates each org under its lock, verifies synthetic envelope decryption and preserves provider generation. Retain old KEKs for backups. It does not fetch/revoke provider keys.
- `retainLibrarian` removes private quarantine/raw data after promotion/expiry and detailed execution logs after 90 days. It retains run tombstones and thirteen months of aggregates. `purgeSubmittedSources` clears private source inputs after account revocation; failures leave raw expiry due for retry.

The root owns route registration in api/index and recovery/retention wiring in jobs/index. Ingestion routes are registered. Their acceptance is queueing only. See ingestion/README for extractor qualification gates and the concrete trusted immutable-source creator. The root job factory consumes ready sources; queued-source extraction orchestration remains absent. Citation-aware source dedup must be proven before promotion is enabled.

The installed official SDK is 1.6.0. runner/provider.ts uses a literal late import with a typechecked SDK boundary, explicit injected key, fixed endpoint, explicit empty auth token/null webhook key, disabled retries and logging. Ambient ANTHROPIC_CUSTOM_HEADERS causes refusal. Mock tests never construct the SDK.

Release blockers: concrete transaction-aware existing editing/read/question adapters with current policy and citation authorization; atomic per-page activity and edit/question result linkage; full proposal/source creation acceptance beyond the focused private regressions; isolated extraction qualification; full private end-to-end acceptance including crash/kill races, transport/promotion escapes, clients, route coverage and viewer checks. Never replace missing adapters with permissive stubs or enable paid dispatch to test them.

Follow-up: proposal GET/reject/create routes are mounted. GET/reject/create work for authorized person sessions with current citation visibility; create stages article content before atomic review and returns 201/200 replay. Detail supplies filtered proposal ids. `ingestion/container-extractor.ts` supplies an isolated local-image Docker adapter; it is not production-wired or fully escape-qualified. See contract 15 follow-up for exact completed checks and remaining gates.

Creation follow-up: `creation.ts` exports `createReviewedProposal` (person-only HTTP review, staged inert article HTML, current same-wiki citation checks, atomic article/version/activity/status/request receipt) and `createImmutableSource` (trusted ingestion staging factory returning a DB-only creator). `promoteSource` uses the concrete creator by default after provenance/fence checks; explicit trusted injected creators remain compatible. Imported sources preserve original bytes and a `__librarian_source.json` provenance file, are archived at creation, refuse unarchive and republish, and remain untrusted. Unreferenced content-addressed stages use normal blob GC; immediate deletion would race another committed reference. Production dispatch stays OFF.

Runtime follow-up: `content-tools.ts` supplies bound-wiki current-token/can()/agentPolicy adapters. Authorization repeats before receipt replay; mutations, questions, proposals, suggestion activity and receipts share the fence transaction. Seeded article reads/edits use explicit supplied-lock editing services. Published reads use checkpoint text rows, board writes refuse, source reads require source role. Questions use deterministic receipt IDs for the thread and comment. Run details filter delegate/question IDs against current page rights. Edit activity carries librarianRun and suggestion IDs.

`createLibrarianJob` defaults to these tools plus guardedAnthropicProvider; private construction can inject a provider and SandboxedExtractor. Queued extraction stages immutable source blobs outside the content transaction, then creates source/text rows and promotes atomically. Runtime source slugs fit the existing 40-character limit. Missing extractor config fails the inbox run before provider construction. Optional LIBRARIAN_EXTRACTOR_ENDPOINT and LIBRARIAN_EXTRACTOR_KEY select only the authenticated remote adapter; never mount a Docker socket in the public server. Hosted executor deployment remains an operational gate.

Runtime completion follow-up: unseeded article edits seed through the supplied document lock. Edit-request checkpoints and direct Delegate finish reuse checkpointLocked with verified blob readback; failures roll back the entire librarian operation. The runner uses prepareAndPersist: preparation holds receipt/content/document locks in one uncommitted transaction, stages and verifies checkpoint blobs without holding the librarian cancellation lock, then acquires that lock and repeats guard plus current authorization before committing mutation/activity/receipt together. Content locks retain the epoch/base/seq throughout preparation, preventing reset/publish races. This deliberately retains an open content transaction during storage I/O; it does not perform an independent draft/checkpoint commit. Cancellation during staging can commit first and forces all provisional content writes to roll back. Orphan content-addressed stages use normal grace-period GC; shared hashes are never eagerly removed.

Source and proposal creators own 40-character-safe UUID-based slugs (source- plus 32 hex, prop- plus 32 hex), preserving collision refusal without overwriting existing content. Every entrypoint writes complete Unicode-safe text chunks with hashes of the stored text. Text and inert sanitized HTML share HTML newline normalization; original source bytes remain unchanged. source_read accepts cursor and optional pinned version, returns bounded blocks with part offsets/full block hashes and nextCursor (null only at completion), and refuses changed versions/invalid cursors. The model tool description requires continuation until complete; the existing run-wide byte/deadline/budget limits still fail explicitly rather than silently truncating a source.
