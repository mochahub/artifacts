# Librarian runner integration

This slice is not wired or enabled. No credential was read and no provider request was sent.

Files: `engine.ts` implements the bounded sequential state machine; `tools.ts` owns the nine tool schemas and deterministic receipt keys; `provider.ts` is the late-loaded official SDK adapter; `receipts.ts` stores mutation results in the caller's fenced transaction; `index.ts` supplies `registerLibrarianJob`; `mockfixtures/runner.test.ts` exercises the private injected provider.

Root owner must add the official `@anthropic-ai/sdk` dependency (official documentation currently lists 1.6.0), then verify installed SDK types against the deliberately narrow structural boundary. The adapter uses explicit key, fixed endpoint, zero SDK retries, adaptive thinking, automatic sequential tools, streaming finalMessage and countTokens. `guardedAnthropicProvider` obtains a fresh key with the frozen `withProviderKey` per operation. No fallback model or price discovery occurs. Rates are the foundation's immutable integer microdollars per million tokens; the contract default is input 2000000 and output 10000000.

`registerLibrarianJob(deps, integration)` returns `{ librarian() }`. Invoke outside the daily jobs transaction. Do not expose provider choice through request data. `RunnerIntegration` is the precise remaining root adapter interface:

- `claim`: atomically claim eligible inbox work or a unique wiki/day and reserve the run. The foundation's claimRun does not bind either work source; it is not a safe scheduler default.
- `cancellation`: subscribe to persistent kill, config/key changes and lease loss on every replica. Install before constructing a provider. Registration adds deadline abort and 30-second heartbeat.
- `provider`: trusted constructor injection; use guardedAnthropicProvider only after integration gates pass. Private tests supply a local object and never load the SDK.
- `tool`: use the supplied transaction; trusted checkpoint blob staging precedes the final durable fence check. Resolve resource references inside the bound wiki, check current selected membership, org-token explicit project ceiling and can(), acquire content lock, then invoke existing PageRead/EditRequest/StartRun/FinishRun operations and agentPolicy. Page/source reads and citations must filter current visibility. Boards may return checkpoint outlines only. Never publish proposed articles or decide suggestions/threads. question must deduplicate a page-level visible-checkpoint comment. propose_page stores a bounded untrusted proposal only. The runner wraps mutations in withToolReceipt under prepareAndPersist; thrown failures roll back the mutation and receipt. The required authorizeTool hook runs inside the fence before reads and receipt replay; it must enforce current per-resource authorization before any stored result is disclosed.
- `disableUnauthorized`: persistent disable/generation increment after 401.
- `finish`: atomically finalize foundation accounting, terminal activity, inbox state and filtered result IDs. Must work on cancelled/expired runs without refunding uncertainty; base finishRun itself requires a live fence.

No generic dispatcher exists. Every complete tool input uses strict schemas; nested edit extras are rejected by canonical parse comparison. Tool output is bounded and tainted. Rules are fetched before any provider call. Thinking remains opaque in memory and is never logged. Truncation/refusal executes no tools. Ambiguous dispatch retains the full ceiling and terminates. Known retryable HTTP failures also conservatively retain their ceilings; at most two retries each reserve a new ceiling. Count failures do not dispatch. Unknown billable categories, over-ceiling usage and missing request IDs become uncertain. Crash recovery relies on foundation pending-attempt recovery and never reuses a reserved attempt as dispatch authorization.

Private checks use `bun test apps/server/src/librarian/runner/mockfixtures/runner.test.ts`; no Docker/shared reset is needed. These unit tests do not prove database crash recovery, real SDK compatibility, policy adapter correctness, cross-replica subscription or full integration. Keep paid dispatch gated until those root integration checks pass.

Follow-up: SDK token counts now reject invalid integers immediately. Tool receipt identity binds run/turn/tool-use id independently of payload hash, allowing changed-payload conflict detection. Private mock regressions pass. Concrete production tool adapters remain absent.

Runtime completion follow-up: unseeded article reads use canonical PageRead Markdown, deterministic legacy block IDs, 12-character edit bases and source order; the first draft seed uses the same IDs. Article continuation is a version:seq:offset cursor and refuses changed version/sequence. Unseeded article edits seed through the supplied document lock. Edit-request checkpoints and direct Delegate finish reuse checkpointLocked.

The runner's prepareAndPersist performs bounded preparation passes. A missing immutable blob or deferred checkpoint computation unwinds and rolls back the current DB transaction before storage or rendering begins. Draft validation, Markdown generation, article rendering/sanitization and staged byte/hash verification run outside that transaction; storage waits observe durable cancellation and a 15-second preparation deadline. The final DB-only pass reacquires content/document locks, compares the originally captured artifact and draft (including version, epoch, sequence, bases and metadata), and rechecks the current run/config/lease, can() and agentPolicy before committing content, activity and receipt together. Any changed snapshot refuses rather than overwriting human work. Operation block IDs and the preparation timestamp remain stable across provisional passes. Unreferenced content-addressed stages use normal grace-period GC; shared hashes are never eagerly removed.

Outer transaction owners registerAfterCommit(tx, queue), drop the queue on rollback and flush it only after a successful commit. docLockIn.after and scoped document/event notifications use that queue, preserving editor/replica update, suggestion, checkpoint and run notices without exposing rolled-back state. Question retries with fresh tool IDs reuse the durable run/page/exact-question-text thread after current authorization; receipt identity remains independently checked.

Source and proposal creators own 40-character-safe UUID-based slugs (source- plus 32 hex, prop- plus 32 hex), preserving collision refusal without overwriting existing content. Every entrypoint writes complete Unicode-safe text chunks with hashes of the stored text. Text and inert sanitized HTML share HTML newline normalization; original source bytes remain unchanged. source_read accepts cursor and optional pinned version, returns bounded blocks with part offsets/full block hashes and nextCursor (null only at completion), and refuses changed versions/invalid cursors. The model tool description requires continuation until complete; the existing run-wide byte/deadline/budget limits still fail explicitly rather than silently truncating a source.
