# Ingestion integration gate

This directory supplies ingestion services and route registration. It does not register itself, enable Librarian, run jobs, provision credentials or invoke a provider.

## Interfaces

- `ingestionRoutes(routes, deps)` in `routes.ts`: register on the standard guarded API Routes instance. Uses the existing `project.publish` action plus selected-wiki checks, pending the root owner's `librarian.submit` action integration. Upload, enqueue, list, detail and cancel routes are provided. Detail/list deliberately omit raw input and source links.
- `enqueueSource(deps, {orgId, wikiId, caller}, request)`: validates the shared SourceInput, checks current publishing rights and wiki selection, verifies completed owned file tickets, serializes idempotency using the foundation org lock, and returns `{item, replay}`. Caller-scoped unique keys include wiki in their canonical payload hash. Enqueue works while OFF and performs no source URL fetch or extraction.
- `extractSource(deps, submission, inboxId, fence, sandbox?)`: checks ownership, current rights, expiry and bound run before I/O. Returns an in-process provenance-bound `ExtractedSource`; OFF/stale fences refuse before URL egress. It does not claim or bind inbox work. The root worker must set `runId` atomically when claiming.
- `promoteSource(deps, submission, inboxId, fence, extracted, trustedCreator)`: rechecks the run and rights under the foundation lock, deduplicates by original byte hash within the wiki, calls the trusted creator in the same transaction and clears raw DB input. The creator must check source visibility on deduplication before granting a caller access. No source link is returned by HTTP here.
- `createUpload`, `ownedInbox`, `cleanupExpiredSources`, `cleanupQuarantine`, `deleteSourceQuarantine`: trusted API/retention integration. Upload ids also become file inbox ids, so their private original and ticket share the required inbox prefix. Ticket expiry is 15 minutes; accepted originals expire after seven days. Range reads plus exact length/hash checks establish completion; there is no separate completion route.

## Required deployment adapter (hosted deployment gated)

Extraction fails with `extractor_unavailable` unless the trusted server construction supplies `SandboxedExtractor`. The interface's limits are requirements, not an OS sandbox. Passing an ordinary callback does not create isolation. A concrete trusted-host Docker adapter is supplied in `container-extractor.ts`; text/HTML/PDF ingestion remains unavailable in the stock hosted deployment. See `deploy/extractor/README.md` for the exact dedicated-host ceiling, private qualification command and remaining release gates. Never give the public app a Docker socket.

Deploy an isolated extractor with no network namespace/egress, read-only runtime, no host filesystem mounts or credentials, 256 MiB hard memory limit, ten seconds CPU plus a wall-clock deadline, a 100-page PDF ceiling and at most 1 MiB UTF-8 output. Use bounded stdin/stdout, kill and reap on overflow/deadline, and destroy each job's temporary storage. Reject symlinks, archives, macros, executables, malformed/polyglot/signature-mismatched input, encrypted PDFs and image-only PDFs. HTML extraction must omit active content and subresource access. PDF extraction requires a maintained PDF parser in that sandbox; no OCR is supported. Prove attempted network/filesystem escapes and resource exhaustion fail before supplying the adapter. There is deliberately no in-process parser or shell fallback.

`TrustedSourceCreator` now has a concrete default adapter in `../creation.ts` using the existing publisher version primitive to create a read-only immutable wiki source, preserving original bytes, hash, submitter, receive time, input provenance, extraction version and `untrusted: true`, using sanitized/checkpoint-derived content. It must enforce existing page-create permission and never publish synthesized model prose. The concrete adapter stages blobs before entering the promotion transaction. Do not pass a general model tool or a network-writing callback into the fenced DB-only transaction. Persist any required blobs before that transaction and make the DB create atomic with the inbox update.

## Network boundary and retention

URL transport uses Node HTTPS with a custom pinned-address lookup, original hostname TLS verification, no connection pooling, no redirects/retries/proxy discovery and only fixed GET headers. It validates all resolved addresses, bounds DNS plus response time to ten seconds and body bytes to 5 MiB. Compression is refused rather than decompressed; identity encoding is requested. Add deployment egress firewall rules denying private/reserved/metadata destinations before use. IPv6 filtering is conservative and rejects transition/special prefixes, including the whole 2001 prefix.

Wire `cleanupQuarantine` into retention even when OFF to delete orphan tickets as well as expired inbox content; it scans the org's private prefix. Call `deleteSourceQuarantine` before inbox/account deletion. Successful promotion immediately removes that item's quarantine prefix; cleanup retries handle a storage deletion failure. Completed immutable artifacts use normal artifact retention. No quarantine GET/download route is supplied.

## Verification and remaining acceptance

Focused tests cover address/URL policy, changed/mixed DNS answers, redirect/MIME/compression rejection policy, filename and signature guards, unavailable sandbox/output bounds, canonical idempotency, concurrent DB enqueue, selected-wiki/current permission checks, private item visibility, incomplete/tampered uploads and replay after ticket expiry. The database tests require an isolated Postgres stack. No provider request or external URL request is made by these tests.

Still required: concrete sandbox and escape/resource fixtures; full deployed source acceptance beyond focused creation/dedup regressions; route registration and route/CSRF acceptance; real pinned TLS/stream overflow/deadline integration tests on private fixtures; run claim/binding and cancellation integration; retention/account-purge scheduling and tests; authorized detail source/proposal links; source promotion crash/race tests. This slice is not a completed Phase 4 release gate.

Follow-up: `container-extractor.ts` and `deploy/extractor` now supply an isolated Docker implementation with immutable local-image injection, no network/mounts, read-only root, hard resource bounds and no fallback. Text/HTML and malformed PDF/output-limit private checks pass. It remains unregistered in production; full escape/resource/PDF qualification remains a gate. Concrete trusted source creation is described below. Promotion now checks current artifact.read in the same wiki before reusing a hash match or replaying an existing source id; a hidden hash match does not grant access.

Concrete creation follow-up: `promoteSource` now defaults to `createImmutableSource` from `../creation.ts`; staging and read-back hash verification happen before the fenced transaction. The transaction rechecks selected-wiki publishing rights and explicit org-token wiki ceiling, creates source/version/activity, and links the inbox atomically. Exact original bytes and submitter/received-time/input/hash/extraction-version/untrusted provenance are normal version files. Imported sources cannot be unarchived or republished. Hidden hash matches create a separate private source rather than revealing/reusing the hidden artifact. Failed stages remain unreferenced for existing blob GC; no shared content-addressed blob is eagerly deleted. Extraction scheduling and production qualification remain separate gates.

Qualification update: dedicated extractor and real TLS fixture suites now exercise the configured container adapter and DNS-pinned HTTPS stream with no provider calls. See the extractor deployment README for successful/denied fixtures and limits. Production remains OFF; this does not qualify a hosted launcher or the complete Phase 4 integration.
